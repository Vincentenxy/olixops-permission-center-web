# 权限中心前端设计

## 本期流程

登录页输入用户名和密码 → 后端校验本地有效用户并签发 JWT → 显示已认证账户概览。刷新时调用 `/auth/me` 重新确认身份；退出后回到登录页。用户名密码错误在表单内提示，服务不可用保留重试机会。

本期没有注册、忘记密码、第三方登录或管理业务页面，不展示无法执行的按钮、虚构统计数据或虚构租户。首个超管通过后端离线命令创建。

## 设计语言

用户于 2026-11-02 确认后续页面沿用 Apple 风格，重点是简洁、明了。官方参考为 [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)，项目使用的社区 skills 来源与固定版本见 [.agents/skills/README.md](../.agents/skills/README.md)。具体页面由本项目实现，社区 skills 不代表 Apple 官方设计或审核。

使用系统字体与接近 Apple 设置界面的清晰排版。主内容保持高对比度和简洁表面，浮动导航或辅助区域可使用一层克制的半透明材质。正文行距舒适，大标题略紧凑；不安装或打包 Apple 专有字体。

颜色、阴影、圆角和间距由公共 token 管理。主操作为蓝色；错误使用文字、图标与颜色共同表达。按压反馈即时，状态转换简短；无装饰性循环动画，不为了弹性效果增加手势库。

移动端保持单列和可触达操作，文本放大时允许自然换行。`prefers-reduced-motion` 减少位移，`prefers-reduced-transparency` 改用实色，`prefers-contrast` 加强边界。输入控件保留真实 label、浏览器自动填充语义和键盘提交。

## 管理页面的应用规则

开发租户、系统、管理员、Token 和审计页面时，以 macOS 系统设置的信息分组与 Finder 的列表效率为参考，按以下规则设计：

- **任务与层级**：页面顶部明确当前位置、标题与当前租户/系统范围；主要内容区域保留一个突出主操作，其他操作按频率放入工具栏、行内或更多菜单。
- **列表与详情**：列表采用紧凑但可读的表格，搜索、筛选、结果和分页组成连续工作区；详情与编辑按基础信息、访问管理等业务含义分组。次要字段通过详情或展开查看，保持关键状态和常用操作可见。
- **视觉与密度**：复用公共字体、颜色、间距和圆角 token；数据表格与长表单使用清晰稳定的实色表面，材质只用于有层次意义的导航或浮层。数据页面把空间留给结果、字段和操作，大幅品牌插画限于登录等展示场景。
- **文案与图标**：标题、字段和按钮使用用户熟悉的业务词，按钮说明实际动作；常用操作保持稳定位置。状态同时用文字和颜色表达，图标按钮提供可访问名称。
- **状态与反馈**：区分首次无数据、搜索无结果、无权访问和加载失败，并给出对应下一步；加载反馈靠近受影响区域，写入时保留输入并防止重复提交。失败提示遵循统一请求层约定。
- **动效与可访问性**：反馈立即发生，过渡只用于说明状态变化和空间关系；频繁操作保持快速，支持键盘、明确焦点、窄屏和减少动画偏好。

页面交付时检查：用户能否找到主操作、看清当前范围与状态、连续完成搜索和编辑；再检查正常、空、加载、错误及权限不足状态。视觉细节沿用当前登录页的配色与控件语言，并适应管理页面的数据密度。

## 前后端契约

| 接口 | 请求 | 成功 data |
|---|---|---|
| POST `/api/v1/pub/auth/login` | `{username,password}` | `{accessToken,expiresAt,user}` |
| GET `/api/v1/auth/me` | Bearer JWT | `{userId,username,name,platformRole}` |

`user` 与 `/auth/me` 返回一致。`platformRole` 为 `platform_admin/none`，租户管理员来自后台成员关系，不由这个字段替代。所有返回使用 `{code,msg,data}`，API 类型与实际 OpenAPI 同步。

成功登录写入当前标签页会话；不能记录密码。前端退出清除标签页凭据；后端 JWT 在到期或用户停用前仍有效，本期没有跨设备会话撤销或 refresh token。

后台系统调用密钥不是管理员 JWT：固定密钥、不自动到期、不实现轮换，只能由系统所属租户的有效管理员创建；后续密钥页面只允许短暂展示创建结果，不保存明文。
